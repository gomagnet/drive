# MagnetDrive context

- Independent file storage web application; reference design: `E:\GolandProjects\Magnet\MagnetServer`.
- Go 1.27, Gin, sqlx, MariaDB, `go.yaml.in/yaml/v3`. Embedded plain HTML/CSS/JavaScript; no frontend build pipeline.
- HTTP uses `gin.Default()` and explicitly sets `gin.DebugMode`, as requested by the owner.
- HTTP installs `internal/middleware.ScraperBlocker`, ported from MagnetServer: three sensitive-path probes in five minutes cause a 24-hour, process-local IP ban (403); the synchronized cache holds at most 20,000 IP records. SFTP is unaffected.
- `trusted_proxies` controls Gin client-IP forwarding for the scraper guard and HTTP sign-in limiter. It defaults to loopback (127.0.0.0/8 and ::1/128), matching MagnetServer; [] disables proxy trust. For Caddy on another host/container, configure only its actual IP/CIDR. Never trust arbitrary forwarded headers from the Internet.
- Serve the embedded root index with `c.Data`, not `FileFromFS("index.html", ...)`: FileFromFS rewrites the request path and Go's file server redirects index.html to ./, creating a root redirect loop even behind a correctly configured proxy.
- Optional SSH/SFTP listener uses `golang.org/x/crypto/ssh` and `github.com/pkg/sftp`. Configure `sftp.listen` and optionally `sftp.host_key`. Preserve the generated Ed25519 host key in the data directory.
- SFTP logs in by account email with the local password or a revocable app password created through Account → SFTP access. Dedicated credentials permit OpenID-only users to connect. Store only token digests; recheck membership and credential validity during transfers and at commit.
- SFTP root contains `/self` and `/shared-<id> - <name>` for accessible spaces. No physical filesystem access, shells, forwarding, links, or modifications of space roots. Same-space rename cannot replace an existing destination. SETSTAT changes are unsupported; clients should disable remote timestamp/permission preservation.
- SFTP writes stage random-key objects, share the web upload limit/slots, publish a version on successful close, enforce quota under the space lock, reject concurrent version conflicts, and abort unclosed transfers on connection failure. SFTP delete moves items to web Trash; rmdir requires no active children.
- Never run builds, create unit tests, or run tests. Only static checks. Do not start the app, database, containers, or browser for validation.
- Module root executable delegates to `internal/drive`. Schema is embedded from `internal/drive/schema.sql`; assets embed in `web/embed.go`.
- Frontend `api()` accepts empty successful responses, including 201 from folder creation/registration and 204 from mutations. Parse JSON only when a response body is present; never assume every non-204 success contains JSON.
- Configuration is YAML. Private configuration, runtime data, and static-analysis cache are ignored. Do not commit credentials or user data.
- OpenID matches verified email for first-time binding and creates an account if no match. Subsequent login uses provider subject. Refresh name/avatar on each login.
- Every user has a personal space; each shared space has a group with owner/editor/viewer roles. Membership and storage changes serialize on the space row.
- Immutable random-key objects live outside public assets. MariaDB stores entries, versions, quotas, memberships, expiring hashed sessions/share tokens, and one-use OIDC state.
- Version rollback changes the current pointer and retains all versions. All stored versions count toward quota. Trash does not reclaim storage; permanent deletion does.
- Public links are read-only individual-file links, follow current versions, expire, and can be revoked. Active HTML/SVG content always downloads.
- Sharing supports Forever (`days: 0`, nullable `shares.expires_at`) and direct `/s/<token>/content` URLs, with force-download variants. GET/HEAD and range streaming use the same token authorization. Revoke invalidates every format of a token.
- `users.is_admin` grants all-space access in HTTP, shared-space management, and SFTP, without inserting artificial memberships. `MagnetDrive admin grant EMAIL` uses existing YAML config, upgrades schema, grants an existing account the role, and exits before starting listeners. Never execute it against the real database as verification.
- Space API responses expose `joined` from the actual membership row, independently of effective admin permissions. Sidebar entries and dashboard "Your spaces"/membership counters include joined spaces only; admin-only non-joined spaces appear in a separate "Other spaces" dashboard block. Keep all-space backend/SFTP permissions and the admin inventory intact. Refresh sidebar membership while preserving the scrolling panel and account controls.
- Account → Administration lists users, grants/removes roles, creates/deletes accounts, and sets personal/shared space limits. Role changes serialize on `administration_lock` to preserve the final admin; self-deletion is refused. Quotas apply to admins too and may be lowered below existing usage without deleting data.
- Admin → Invite a user creates hashed, single-use invitations with a 1–168 hour expiry (UI default 72), optional bound email, and optional shared-space viewer/editor membership. `/invite/:token` renders the embedded page directly; public info/accept endpoints validate the token and active issuing admin. Public registration may remain disabled. Never merge/overwrite existing accounts or let recipients choose grants/admin status.
- Invitation claim serializes on `administration_lock`, locks the invitation/target space, and atomically creates the normal user, personal space, saved membership, consumed marker, and login session. Admins list/revoke pending links; issuer demotion/deletion revokes its links, and expiry cleanup removes old rows. At most 1,000 active pending links. `web/invitations.js` supplies localized admin/recipient flows. Keep the native browser `history` object available; version history UI uses `versionHistory()`.
- User deletion revokes sessions/identities/SFTP credentials/memberships/public links, anonymizes the user row for audit FKs, transfers owned spaces to the acting admin, and converts the personal space to archived shared storage. File history stays available; permanent file deletion remains a separate action.
- Account → User settings edits name/avatar/theme and password. Require an existing local password to change it; an authenticated OpenID-only user can set an initial one. Password changes revoke other browser sessions. OIDC still refreshes name/avatar on each provider login.
- User settings → API access manages up to 20 hashed API keys per user, with `read`/`write` scope, optional one-space restriction, nullable expiry (0–365 days), and coalesced last-used tracking. Secrets are returned once. Account deletion revokes keys; password changes leave these independent credentials intact.
- `/api/v1` is bearer-only (no cookie fallback). API keys cannot reach account/admin/key-management endpoints. Only versioned API mutations without Origin bypass the browser CSRF check; any supplied Origin must still match public_url. Do not weaken session-route CSRF protection or enable broad CORS. File access and locked mutations recheck key restrictions/expiry/revocation as well as existing user/space permissions and quotas.
- `internal/drive/api_v1.go` reuses file handlers for versioned metadata, folder creation, multipart upload, download/ranges, rename, bulk move/trash/restore/purge, versions/rollback, and share links. API list pages use increasing IDs, limit 1–1000 (default 200), `after`/`next_cursor`; web lists retain their existing ordering. Folder creation now returns its ID as JSON. `API.md` and public embedded `/openapi.json` describe the contract. `web/api-keys.js` supplies localized management UI.
- English/Russian localization uses `web/i18n.js` and the embedded `web/i18n-ru.json` catalog. Wrap UI HTML/messages in `ui` tagged templates and plain labels/errors with `t()`. Templates translate source text/labels before substituting values; keep data interpolations escaped as before. Never translate API identifiers, enum/control values, URLs, filenames, user/space names, or file/editor contents. Do not add a broad DOM text-replacement observer.
- Browser drag detection must compare the literal DataTransfer type `Files` and item kind `file`, never `t('Files')`. These are protocol identifiers even though "Files" is also a UI translation key. File drag detection may fall back to items/file-list presence; preserve the dragover preventDefault that enables drop.
- `users.language` defaults to `auto` and accepts `auto`, `en`, or `ru`. Profile PATCH treats an omitted language as unchanged, so theme-only saves do not reset it. Startup/account settings restore the saved preference; automatic mode follows the browser's primary language (`ru*` → Russian, otherwise English). Browser storage retains the latest preference for anonymous pages. Dates and byte units follow the selected locale.
- `i18n.ready` loads the local catalog before app startup; the brand is rendered lazily so it uses the current language. Profile language changes redraw translated chrome while retaining in-memory form drafts; system language changes wait for dialogs/uploads to be idle. Password drafts are never put into storage or the catalog.
- `web/browser.js`, `web/settings.js`, and `web/sharing.js` extend `app.js`; all are embedded/routed locally. Startup waits for DOMContentLoaded so deferred modules are defined before requests start. Upload completion patches table content/storage figures, not the main page/shell. Single click selects, double-click/Enter opens; parent navigation uses backend ancestry. Whole-window file drops and accessible context menus support the browser flow. System/light/dark themes have monitor/sun/moon icons.
- Match Magnet's application mark, sidebar, restrained panels, blue accents, automatic/light/dark themes, responsive layout, and scale/fade dialog transitions. Backdrop/Escape closes dialogs; respect reduced motion.
- `web/scrollbars.css`/`scrollbars.js` adapt MagnetShared's themed scrollbar implementation. Modern Popover/ResizeObserver browsers hide native gutters and paint accessible draggable overlay controls, including inside dialogs; unsupported browsers keep themed thin native scrollbars. The sidebar scroll area uses negative inline margins plus matching content padding so its rail aligns with the panel edge. Overlay scrollbars reserve no content space. Localize scrollbar labels and keep context menus open when their overlay scrollbar is dragged.
- See README for setup, backup requirements, API limits, and outstanding production hardening. Do not claim runtime or visual verification from static checks.
